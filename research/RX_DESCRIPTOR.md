# BE v2 RX descriptor metadata

Source boundary: retained Linux commit `c03c1a14507dfaf8b856c2608f9ac216021fc222`, `txrx.h:489-589` and `rtw89_core_query_rxdesc_v2` in `core.c:4163-4240`. This is a source-derived portable decoder, not hardware validation.

`decode_be_rx_metadata(bytes, configured_fcs)` first calls the existing strict `decode_usb_rx_be` aggregate parser, retaining its descriptor/metadata/payload bounds and 16-byte aggregate alignment. It then decodes only established descriptor fields: normal packet type0, frame type, MAC ID, security type, CRC32/ICV flags, hardware/software decryption, AMPDU, CAM validity, PHY selection, raw rate/BW/GI-LTF/PPDU codes and free-run counter. Rate/BW remain source codes rather than guessed human rates. The short descriptor is24 bytes, long40; optional metadata lengths remain explicit. No channel number is present in these fields, and no channel is invented from a configured scanner channel.

HDR_CNV is dword7 bit16 and exists only in the long descriptor. Therefore `header_converted` is optional: short descriptors leave it unknown. `normal_80211_candidate()` excludes errors/conversion and requires separate verified no-conversion profile evidence for short descriptors. A long HDR_CNV=false establishes the descriptor's unconverted framing; management frame validation still belongs to the 802.11 parser. Long dword9 exposes raw header offset and wireless header/IV length; these are not silently applied to payload addressing because source v2 parser does not do so.

FCS presence is **not** the CRC error flag. The retained descriptor layout has no per-packet FCS-included field. Source MAC setup sets `B_BE_APPEND_FCS` (`mac_be.c:1012`) and source hw setup declares `RX_INCLUDES_FCS` (`core.c:7497`); an executor that actually applies/verifies that MAC configuration can pass `RxFcsPolicy::appended`. Without such evidence the decoder leaves FCS presence unknown and refuses to strip bytes. FCS policy is attached only to normal payloads, never C2H records. `payload_without_fcs_bytes` rejects unknown policy and appended payloads shorter than4 bytes. It does not validate a CRC checksum itself.

Tests cover short/long layouts, exact source CRC/ICV bits, raw rate/BW, unavailable short framing indication, long header conversion, explicit appended FCS, missing policy refusal, and truncated long descriptors. Strict-warning standalone C++ test passes. No USB actions were performed for this decoder.
